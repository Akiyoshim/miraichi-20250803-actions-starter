# GitHub Actionsの設定と実行

このリポジトリの自動化は GitHub Actions で動きます。GitHub Actions は、GitHub上でプログラムを実行できる仕組みです。今日のセミナーでは、次の4つだけ覚えれば十分です。

## 覚えるのは4つだけ

1. **GitHub上でプログラムが動く** — 自分のパソコンやサーバーを用意しなくていい
2. **時間を指定して定期実行できる** — 毎朝決まった時間に自動で動く
3. **手動でも実行できる** — Actionsタブのボタンから、好きなタイミングで動かせる
4. **実行結果とエラーを画面で確認できる** — 何が起きたか、あとから読める

GitHub Actionsは本来、テストの自動化やビルド・デプロイなど、エンジニアのCI/CD（開発作業の自動化）に使われるツールです。今日はその一部（定期実行の仕組み）だけを、情報収集の自動化に使います。

小規模な個人利用であれば、各サービスの無料枠を活用して始めやすい構成です。ただし GitHub Actions・Gemini API・Resend には、それぞれ利用条件と上限があります。使う量が増えれば費用が発生することもあるので、始める前に各サービスの最新の条件を必ず確認してください。

## Secretsとは

APIキーのような秘密の情報は、コードに直接書かず **Secrets** に登録します。

- Settings → Secrets and variables → Actions から登録する
- 登録した値は、実行中のプログラムからは読めるが、画面には表示されない
- ログにも値は出力されない（安全に管理できる）

## 手動で実行する

1. リポジトリの **Actions** タブを開く
2. 左の一覧から **daily-digest** を選ぶ
3. **Run workflow** ボタン → 緑の **Run workflow** を押す
4. 実行が終わる（緑のチェックになる）のを待ち、自分のメールを確認する

## 実行ログを確認する

Actions タブ → 実行履歴 → 各ステップを開くと、何が起きたかが順番に表示されます。

- 緑のチェック … そのステップは成功
- 赤いバツ … そこで止まっている

赤くなった行を開くとエラーの内容が文章で出ています。原因はたいていこの中に書いてあります（詳しくは [troubleshooting.md](troubleshooting.md)）。

## 実行時刻を変える

`.github/workflows/daily-digest.yml` の次の行を書き換えます（UTC表記。日本時間−9時間）。

```yaml
    - cron: "0 22 * * *"   # 22:00 UTC = 日本時間 翌朝7:00ごろ
```

例: 日本時間 12:00 に受け取りたい → `"0 3 * * *"`。

なお GitHub のスケジュール実行は混雑状況により数分〜数十分遅れることがあり、分単位で正確な定刻実行はできません。また、リポジトリに60日間更新がないとスケジュール実行は自動で無効化されます（Actionsタブで再有効化できます）。

## 重複防止のしくみ

送信済み記事のURLは `data/processed-items.json` に記録され、実行のたびにワークフローが自動コミットで書き戻します。同じ記事が翌日もう一度届くことはありません。
